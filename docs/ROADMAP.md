## M0.4.1 · 三维镜头与可拖拽进度轴（2026-11-13）

本轮基于实际 Chromium 1280×720、390×844 截图复核，针对近景暴露建模侧面的问题重设了镜头路线：不再从几乎纯侧向贴脸环绕，镜头沿江面正侧缓慢取景；透视相机使用桌面33°/竖屏34°镜头，竖屏通过按宽度后撤机位适配，绝不再使用58°广角。不同章节采用相机关键帧插值，岛体、洞口、船只和码头构图可以倒放与随机访问。

- [x] 更自然的岩面石纹、山顶林冠、低饱和青绿配色、水面远处雾化和异形岸台。
- [x] 原三幅 Pixi 高清背景完全未动，Three.js 只做入口、卷尾视觉叙事。
- [x] **真实拖拽进度**：自定义可捕获指针的滑轨，鼠标/触控从轨道任意位置按下拖动；滑动更新三维镜头、游船、角色位置，支持倒拖、章节点击、播放/暂停/重播。键盘 Home、End、左右方向、PageUp/Down 可操作。
- [x] 正常播放结束进入 Pixi；人工拉到末尾则停止以便观看画面，提供「继续游历 · 进入长卷」。卷尾保留停留与返回画卷入口。
- [x] CI 中使用 Playwright + 真实 Chromium/SW SwiftShader、Noto CJK 字体进行桌面和竖屏分镜截图，并覆盖 **鼠标实际拖拽、键盘 seeking、跳过序章、卷尾返回**。
- [ ] 角色只有单张立绘，并不是严格的跨船/跨台阶骨骼动画；岸台位置和象山模型是艺术化布景，非精确景区测绘。后续可在授权 3D 地形、分层模型到位后增强。
- [ ] 当前视觉检查为自动化无头浏览器；仍需真实手机 Safari 和实体 GPU 复核。

**自动化**：\`.github/workflows/visual-qa.yml\` 每次修改 Three.js 场景自动拍摄关键帧并上传 \`threejs-camera-frames\` 供审查。构建及 Pages HTTP smoke test 仍在 \`pages.yml\`。
